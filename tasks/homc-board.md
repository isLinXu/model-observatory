# 模型清单核实栏目（HOMC）

把 `isLinXu/model-list` 的 🆕 / 🔄 / ⚠️ 三态核实总表接成每天可核对的一栏：本站逐行数过表格行，与它「核心统计」里对自己的说法并排公布，页面开一个独立栏目。接入的是**已发布的站点与其 README**，不是把两份清单交叉引用的工程。

## 验收口径

- **实测与自报并排、永不相加、也不互相改数**：`measured.rows.total` 是本站在抓到的字节里数出来的表格行，`self_reported.increment` 是清单写给自己的说法，`comparison.delta` 只把差发布出来；`200+` 这类区间原样保留，取整就成了本站的数字。本站的 Hugging Face 下载观测与该清单的条目不是同一批对象，两侧都不加。
- **核实归它，本站只转述**：A / B / C 来自该清单的信息来源列，页面只能说「这份清单把这一行标成 A」。`single_b_source` 按形状判定（该行只标了一个 `[B]`），与清单自己写的「须复核」说明并存而不互改。
- **两种「新」分开**：`as_of` 是他们标注的核实截止日（并单独报月龄），`cadence` 是 `README.md` 上次何时被提交——该仓库的提交里含自己的每日自动日报，所以「日更」说的是文件动过，不代表人工核实表每天核一遍。
- **表格只是样本**：三态轮转取前 `ROW_LIMIT` 行（每态内部按新→旧），砍掉的是样本尾巴，行数、等级分布与台账都不因此变小；轮转的理由是预算砍尾巴时不能把 🔄 与 ⚠️ 砍到整栏没有。
- **增删由 id 台账算**：id 是 `homc:<名称 slug>|<提供方 slug>`，第一次读到只建基线（报「基线」而不是 0 或一堆新增），台账被 id 上限截断时增删按下限报告。
- **没读到不等于读到 0**：抓不到或认不出既定列时沿用上次快照并标 `stale`，`unavailable` 时页面每个数字都是 `—` 且说明「这次没读到」——包括「口径与告警」那一栏：没读到不能宣布「没有告警，总表读到了」。
- **载荷只有结构**：原始 Markdown 不进载荷，说明限 160 字符、每行最多 4 个链接，所有链接发布前重过 `http(s)` 白名单；快照 160 KB／台账 200 KB 各有预算，超预算削的是样本行数。`data/homc_ledger.json` 每天随快照提交进公开仓库（增删靠它），但不进 `_site/`、页面也不请求它。
- **懒加载不占首屏**：`IntersectionObserver` 盯住 `#homc`，进视口才发那一次请求（连同历史共两次），刷新按钮说的是「只读本站已发布的文件，不去抓别人的仓库」。
- **建行只抄那行说过的话**：「建卡」把名称、提供方、清单给的出处／类别／日期与「来源等级由该清单判定」写进本机草稿，状态从 `proposal` 起，本站任何计数（行数、样本窗口、预算）都不进卡片；id 认不出名称部分就拒绝，不发明文件名。
