# 论文清单跟踪接入每日采集

把六个公开 awesome 清单变成每天可核对的观测：内容计数、更新节奏、新增与移出，页面上开一个独立栏目。

## 验收口径

- 实测与自报分列，永不相加；上游仓库（BradyFU）的行数不进本站合计。
- 增删由条目 id 台账算出：第一次读到只建基线，滚动窗口的移出不算丢失，认不出行按清单换格式处理而不是发布 0 条。
- 更新节奏按文件问提交历史，不按仓库的 `pushed_at`；停更与「今天没读到」是两件事。
- 载荷只有结构：无原始 Markdown，链接过 `http(s)` 白名单，索引 120 KB／台账 200 KB 各有预算，超预算时削样本尾巴而非数字。

## 后续（2026-11-03 审核留下）

- 已做（2026-11-03）：论文流水每行尾多了「建卡」——一行样本变成一个本机任务草稿（`mo.board.edits.created`），推送才成为 `tasks/<slug>.md`。文件名跟着 arXiv id（`arxiv:2611.01790` → `paper-2611-01790`），于是同一篇论文在两份清单里落同一个 slug，第二次点说的是「已经在看板上」而不是复制一张；既没 arXiv id 又没条目 id 的行直接拒绝，不发明随机名。卡里只抄这一行自己说过的事实（来源清单、链接、分区），条目数／覆盖率／节奏一概不进来，状态固定从 `proposal` 起——清单担保过这篇论文存在，没替你决定要不要读。真实快照上浏览器实测：首页 25 行对 25 个按钮，点第二行得到 `paper-2611-01790`、卡片当场画在画布上、toast 写「它还在这台浏览器里」，验收后草稿已清空。第一次实测顺手抓到一处排版缺陷：正文各段被 `filter(Boolean)` 连同当作分隔的空行一起滤掉，推送出去会是一整块不分段的文字——改成按空行拼段，并补了「没有分区的行少一段而不是多一个空段」的断言。
- 已做（2026-11-03）：「样本太少，看不出趋势」补上了一个可以回来的日子。`awesomeTrend()` 多出 `readyOn`＝最后一个已记录日＋还差的点数（每天一次的节奏推算），图注写成「……第 3 天起才有净变化——按每天一次的节奏推算，2026-11-05 才够 3 个点，本站不补造历史」。它是**排期不是观测**：漏跑一天就顺延一天，历史文件里不会因此多出任何点。今天真实的文件只有 1 个点，浏览器里读到的正是 2026-11-05；三点齐了 `readyOn` 就是 `null`，那句话整条消失。测试钉住两件事：1 个点推 2 天、2 个点（21 与 23 日）只推 1 天——按已记录的天数算，不按日历跨度算，缺 22 日这件事不会让日期提前。
