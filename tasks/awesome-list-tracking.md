# 论文清单跟踪接入每日采集

把六个公开 awesome 清单变成每天可核对的观测：内容计数、更新节奏、新增与移出，页面上开一个独立栏目。

## 验收口径

- 实测与自报分列，永不相加；上游仓库（BradyFU）的行数不进本站合计。
- 增删由条目 id 台账算出：第一次读到只建基线，滚动窗口的移出不算丢失，认不出行按清单换格式处理而不是发布 0 条。
- 更新节奏按文件问提交历史，不按仓库的 `pushed_at`；停更与「今天没读到」是两件事。
- 载荷只有结构：无原始 Markdown，链接过 `http(s)` 白名单，索引 120 KB／台账 200 KB 各有预算，超预算时削样本尾巴而非数字。

## 后续（2026-11-03 审核留下）

- 已做（2026-11-03）：日常采集的首次 CI 运行把 `sizes` 与 `recent` 都发布出来了——索引 68,266 B／预算 120 KB、台账 92,388 B／200 KB，六行全部带年龄分桶，`skipped` 三拆生效（`awesome-native-multimodal-models` 本轮 193 行按「无链接」归账），`paper-list` 的最新归档月距今 2 个月，历史里 `tracked: 6` 与 `retention` 都在。页面不再走缺失降级。
- 待办：`isLinXu/awesome-native-multimodal-models` 本轮 193 行「认不出链接列」——值得抽查那几行是真的表格行还是分节标题被误判；若是格式差异，按清单调行准入而不是抬计数。
- 已做（2026-11-03）：单文件 2.5 MB 撞线不再静默切片——`measured.byte_capped` 与 `files[].truncated` 落在载荷里，告警与卡片都写「实测条目数是下限」，前端「需关注」筛选把它列成一条原因（最大实档 1,073,876 B，仍未撞）。
- 已做（2026-11-03）：`Fetcher.text` 记下每次的失败原因（`no_budget` / `missing` / `http`），`fetches.budget_hit`、`fetches.max_files` 与 `measured.topics_not_attempted` 进载荷；「本轮没问到」和「服务器说没有」不再是同一个 404。`skipped` 同时拆成 `skipped_no_title` / `skipped_no_link` / `skipped_no_signal` 三个可对数的原因，报告类清单按会议或日期认出的行不再被当成非条目（`unlinked_rows` 单独公布）。新加的 `measured.recent` 年龄分桶与 `newest_month_age_days` 只用已下载的字节算，不多打一次请求。
- 已做（2026-11-03）：卡片明细多了一行「实体注册表」——列出把这份仓库登记为 `gh_repo` 对象的实体条目与对象状态，点 chip 到注册表反查；这一行只说关系，不抄任何计数。没登记的写「还没有条目登记这份仓库」，注册表还没载入就说不载入，不写 0。
- 已做（2026-11-03）：「只看这份」把卡片与论文流水一起收敛到单一清单（与搜索／形态／归属／节奏／状态同一条过滤链，虚线 chip 常驻提醒并可一键取消）；CSV 补 `snapshot_status` 与 `list_read_today` 两列，20 列，让「沿用的数字」在表格里也能整条筛掉。
- 已做（2026-11-03）：`--check` 的退出码口径定了——**`partial` 返回 0**，六个清单多数是别人的仓库，某份今天读不到是观测结果而不是采集器坏了；天天红的信号等于没有信号。本地看到的失败信号改由打印付账：标题带状态词（`check partial: …`），汇总末尾追加「本轮没读到（数字是沿用的）：owner/name…」与「抓取预算 80/80 已用尽」，并打印本次十条告警（以前 `--check` 一条都不打）。升级成 CI 告警是工作流那一步的职责，已经接线并实测：抽出「Report list tracking sizes」的脚本体在当前快照上跑，只发出基线那条 `::warning::`（6 份仍在搭基线），其余分支按数据缺失保持安静、退出 0。`unavailable`（一份都没读到）才返回 1。两个语义各有测试钉住。
- 已做（2026-11-03）：浏览器实测过一遍当日真实快照——趋势只有 1 个点时写「样本太少，看不出趋势」，`sizes`／`recent` 缺失时对应行整条不出现；「只看这份」把 6 张卡收到 1 张、虚线 chip 显示「只看 …（余 1 份，点此取消）」并能一键还原；卡片里的「实体注册表」行在本地重跑 `collect_entities.py`（5 条 → 11 条）后亮出 `paper-list · 已核对` 的 chip，点它注册表进入「1 / 11 ENTRIES · 反查中」并给出「关系归那个栏目，条目数与节奏仍在这里」的 toast，那一行本身不出现任何计数。工作流里实体索引排在清单采集之后，所以每天发布的索引都带得上面的链接；无 console 报错。
- 已做（2026-11-03）：`data/awesome_history.json` 有了读者——栏目里的「逐日观测趋势」画自有/上游实测条目两条线（不相加），另可切到「当日可读清单数」；不足 3 点写「样本太少，看不出趋势」，`repos < tracked` 的日子在图注点名「那天是沿用的数字」。历史文件按最近 120 天逐日、更早每月留最后一个真实点收敛体积，规则随 `retention` 发布；读不到历史只空着这张图，不影响当日快照。
