# 实验代码审计

目标：在修改之前先建立对代码的正确认知，避免把症状当病因。

## 流程

1. **静态阅读**：按调用链自顶向下读，不要从入口文件逐行读。
2. **列出真实问题**，每条必须附上：文件、行号、触发条件、后果。
3. **区分严重度**：会导致错误结果 > 会崩溃 > 会浪费时间 > 风格问题。
4. **先修严重度最高的一条**，改完立刻验证，不要批量改。

## 纪律

- 每个结论都要能被验证工具或最小复现支撑，不接受「看起来有问题」。
- 审计算法时，主动构造反例：空输入、单元素、超长、重复、非法值。
- 数值代码要检查：浮点比较是否用了容差、随机种子是否固定、
  归一化是否可能除零、累加是否在 fp16 下溢出。
- 发现测试缺口时，先补一个能失败的测试，再修实现。
